# Narration and character voices

Prof. Sen narrates each lesson, the cast speak their on-screen lines, and characters react to the learner's choices. All audio is generated **ahead of time** with Google Cloud Text-to-Speech and bundled as MP3 files. The app never calls a TTS API, never needs a network connection for audio, and never sees the API key.

## Where things live

| Path | What it is |
|---|---|
| `src/features/audio/clips.ts` | **Source of truth.** Every clip: stable id, lesson, character, style, and the exact text that is spoken. The five original lessons' lines are written here; the curriculum lessons' lines are merged in from `curriculum-clips.ts`. |
| `src/features/audio/curriculum-lines.ts` | Derives a curriculum lesson's spoken lines (intro heading and lines, concept line, transfer feedback, takeaway) from its content. |
| `src/features/audio/curriculum-clips.ts` | **Generated** by `npm run tts:curriculum` from `supabase/seed/content.json`. |
| `src/features/audio/voices.ts` | One Google voice per speaking character, speaking rate, output format, audition candidates. |
| `src/features/audio/reactions.ts` | Picks the reaction clip for a resolved outcome (e.g. goal vs save). Reads game results only; never changes them. |
| `src/features/audio/controller.ts` | Playback rules: one clip at a time, queue vs replace, once-per-run dedupe, mute, stale-callback protection. |
| `src/features/audio/expoBackend.ts` | The single `expo-audio` player behind the controller. |
| `src/features/audio/narration.ts` | App-wide controller instance; mirrors the mute setting; stops audio when the app is backgrounded. |
| `src/features/audio/useNarration.tsx` | `NarrationScope` (in `LessonShell`), `useNarrateOnMount`, `useNarrateOnEvent`, `<NarrateOn>`, `<NarrateOnMount>`. |
| `src/features/audio/audio-manifest.ts` | **Generated.** Static `require()` map of clip id → bundled MP3. Only lists files that exist. |
| `assets/audio/<lesson-id>/<clip_id>.mp3` | Generated audio, committed with the app. |
| `assets/audio/clips.lock.json` | Generated. Hash of text + voice per clip, used to detect stale audio. |
| `scripts/generate-tts.mjs`, `scripts/tts-lib.mjs` | Local generator. Never imported by the app. |

Stories use the same pipeline for their lines (`src/features/audio/story-clips.ts`, generated by `npm run stories:clips`) and add music and ambience on top: see [STORIES_CINEMATIC.md](STORIES_CINEMATIC.md).

## How playback behaves

- A lesson's intro is narrated when the lesson opens; each step's dialogue plays once when it appears, in on-screen order.
- Choices trigger reactions *after* the outcome is resolved (Lesson 1 reveal, Lesson 2 round results, Lesson 3 meetups, Lesson 4 every shot, flipping the incentive in Lessons 1 and 5, checking a transfer answer). A newer reaction replaces the previous one; nothing waits for audio.
- Each line plays at most once per visit to a lesson. Re-renders, Strict Mode, going Back and Forward, and restoring a saved lesson do not repeat lines; reactions only fire for actions taken now, never for restored state. **Replay** on the completion screen starts the narration over.
- Moving to another step stops the previous step's audio. Leaving the lesson or backgrounding the app stops everything.
- Tapping a spoken dialogue bubble replays that line.
- **Mute**: the speaker button in the lesson header, or *Settings → Narration*. Both write the same persisted setting (`settings.narration` in the progress store, on by default). Muting stops audio immediately; unmuting does not replay what was skipped.
- A clip with no audio file (not generated yet, or failed) is skipped silently and the line is shown as usual.

## One-time Google Cloud setup

1. In the [Google Cloud console](https://console.cloud.google.com/), create or pick a project and make sure billing is enabled.
2. Enable the **Cloud Text-to-Speech API** (APIs & Services → Library).
3. Create an API key (APIs & Services → Credentials → Create credentials → API key).
4. **Restrict the key** (Edit API key):
   - *API restrictions* → Restrict key → select **Cloud Text-to-Speech API** only.
   - *Application restrictions* → **IP addresses**, listing the machine(s) you generate audio from (optional but recommended). Do not use Android/iOS app restrictions: the app never uses this key.
5. Optionally set a budget alert. The full library is about 9,000 characters (85 clips); regenerating it is cheap, but bounded is better.
6. Copy `.env.example` to `.env` in the project root and set:

   ```
   GOOGLE_TTS_API_KEY=your-key
   ```

`.env` is git-ignored. Never rename the variable to `EXPO_PUBLIC_…` — that would embed it in the app.

## Generating audio

All commands run from the project root.

```bash
npm run tts -- --dry-run
```
Validates the manifest and lists what would be generated. No API calls, no writes.

```bash
npm run tts -- --list-voices en-IN
```
Lists the voices currently available to your key.

```bash
npm run tts:audition
```
Writes `.tts-audition/<character>/<voice>-{neutral,question,reaction}.mp3` for every candidate in `voices.ts` (or `npm run tts:audition -- maya` for one character). These files are git-ignored and never bundled. **Do this before generating the library** and pick voices by listening.

```bash
npm run tts -- --only l1.intro.sen
```
Generates a single test clip.

```bash
npm run tts
```
Generates every clip that does not have a file yet, then rewrites `audio-manifest.ts`. Before any synthesis it checks every configured voice against the live voice list and stops if one is missing.

The generator:
- skips existing files unless told otherwise;
- retries network errors, 408, 429 and 5xx with backoff (4 attempts), and stops early on 401/403;
- validates each response is real MP3 audio, writes via a temp file and rename, and records progress after each clip, so an interrupted run keeps what finished;
- reports failed clip ids at the end and exits non-zero;
- never prints the key (errors are redacted, and the key goes in the `X-Goog-Api-Key` header, never a URL).

### Regenerating

| Goal | Command |
|---|---|
| One clip after editing its text | `npm run tts -- --only l2.types.meera --force` |
| Several clips | `npm run tts -- --only l4.shot.save-read,l4.shot.goal-read --force` |
| One lesson | `npm run tts -- --lesson predictability-trap --force` |
| Everything (deliberately) | `npm run tts -- --force-all` |
| Rebuild the app map only | `npm run tts -- --manifest-only` |

`--force` without `--only` or `--lesson` is refused on purpose. Runs report clips whose text or voice changed since generation as **stale**, and `npm test` fails while any bundled clip is stale.

### Changing a character's voice

1. Audition: add candidates to `auditionCandidates` in `src/features/audio/voices.ts`, run `npm run tts:audition -- <character>`, and listen.
2. Set `name` (and, if needed, `speakingRate`) for that character.
3. Regenerate their clips. Every clip for that character is now stale; regenerate them by id, or by lesson with `--lesson … --force` (this also regenerates other characters in that lesson).

### Adding or editing a line

1. Add or edit the entry in `clips.ts`. Ids look like `l<lesson>.<step>.<line>` and must never be reused for different text.
   - `sync: 'screen'` — text is shown verbatim on screen; a test checks the lesson file still contains it.
   - `sync: 'computed'` — text comes from the same function or data the screen renders.
   - `sync: 'spoken'` — a spoken form of the screen text (e.g. "⅔" as "two-thirds") or a short reaction to an outcome already shown.
2. Reference the id from the component: `<Dialogue clip="…">`, `<StepHeading clip="…">`, `<Panel clip="…">`, `<Completion takeawayClip="…">`, a `TransferOption.clip`, or `<NarrateOn clip="…" trigger={…} />` for a reaction.
3. `npm run tts -- --only <id>` and commit the MP3, `clips.lock.json` and `audio-manifest.ts`.

### Curriculum lessons (the 17 on the shared runner)

Their text is content, loaded from the database, so their clips are not written by hand. Ids are `<lesson-id>.<step>.<line>`, e.g. `auctions.transfer.curse`.

1. After curriculum content changes, refresh the seed (`npm run content:pull`), then `npm run tts:curriculum` to rewrite `curriculum-clips.ts`. A test fails while the snapshot and the seed disagree.
2. `npm run tts` generates the new clips. Edited lines show up as **stale**; regenerate them with `--lesson <lesson-id> --force`.
3. Commit the snapshot, the MP3s, `clips.lock.json` and `audio-manifest.ts`.

At run time the lesson runner plays a clip only while its generated text still equals the text on screen, so a line edited in the database stays silent (never wrong) until its audio is regenerated and shipped. In development it logs a `[narration] … has no generated audio for its current text` warning.

## Testing playback

Automated (`npm test`) covers the controller with a fake player, manifest validation and text drift, reaction selection, settings persistence, and the generator with a mocked API. It never calls Google.

Manual checks after generating audio:

- **iOS / Android**: `expo-audio` is included in Expo Go for this SDK, so `npx expo start` and open in Expo Go works. Also check a development or preview build (`npx expo run:ios|android`, or `eas build --profile development`) since release builds bundle assets differently. Check: intro plays on opening a lesson; lines queue rather than overlap; tapping Continue mid-line cuts it off; rapid shots in Lesson 4 only voice the newest; muting stops audio instantly; leaving a lesson or backgrounding the app stops audio; airplane mode makes no difference.
- **Web**: `npx expo start --web`. Browsers block audio until the page has had a user gesture, so a lesson opened from a direct URL may stay silent until the first tap; opening it from the home screen counts as a gesture.
- **iOS silent switch**: narration plays with the ringer off (`playsInSilentMode: true`), because it has its own mute. Change this in `expoBackend.ts` if that is not wanted.

## Verifying the key is not in the app

- The key is only read by `scripts/generate-tts.mjs` via `process.loadEnvFile`. No file under `src/` or `app/` reads `process.env`, `.env` or the variable name; a test enforces this for `src/features/audio`.
- Check a production bundle:

  ```bash
  npx expo export --platform all --output-dir dist-check
  ```
  ```bash
  grep -rl -e "GOOGLE_TTS_API_KEY" -e "texttospeech.googleapis" -e "AIza" dist-check
  ```
  The grep must print nothing. Delete `dist-check` afterwards.
- `git status` must never show `.env`. It was previously tracked (empty); it is now removed from the index and ignored.
