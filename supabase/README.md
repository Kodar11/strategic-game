# Supabase

| Path | What |
|---|---|
| `migrations/` | Schema, row level security, functions. Apply them in filename order. |
| `seed/content.json` | The content catalog snapshot (see `docs/DATA_ARCHITECTURE.md`). |
| `seed.sql` | Generated by `npm run content:seed-sql`. Imports the snapshot and assigns lesson categories. Safe to re-run. |
| `daily/examples.sql` | Runnable Daily Challenge publishing statements (see `docs/DAILY_CHALLENGE.md`). |
| `daily/manage.sql` | The Daily Challenge SQL Editor workflow (see `docs/SQL_EDITOR_OPERATIONS.md`). Tested. |
| `games/schedule.sql` | Makes sure this week and the next seven have a Game of the Week (automatic rotation). |
| `games/manage.sql` | The Game of the Week SQL Editor workflow: schedule a game (e.g. Gambit), rotation, audit, boards, champions. Tested. |
| `scheduler.sql` | Registers the one pg_cron job (`content_admin.run_scheduled_jobs()` every 5 minutes) and verifies it. |
| `functions/arena-match/` | Edge Function that runs ranked Strategy Arena matches on the server (see `docs/GAME_OF_THE_WEEK.md`). |
| `__tests__/` | Migrations, seed and RLS tested in an in-process Postgres (PGlite). Part of `npm test`. |

## Setting up a project

1. **Dashboard → Authentication → Sign In / Providers → Allow anonymous sign-ins: on.** The app signs every install in anonymously. Consider enabling CAPTCHA or keeping the default rate limits.
2. **Dashboard → SQL Editor:** run each file in `migrations/` in order, then `seed.sql`.
   - The import prints a count per entity and action (all `inserted` on a new project).
   - The `validate_content()` query must return no rows; the last query reports how many lessons got a category (22 on a new project).
   - With the CLI, the same steps are `npx supabase link` then `npx supabase db push`, then run `seed.sql` with `psql` against the database connection string.
3. Put the project URL and the **publishable** key in `.env` as `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_KEY`.
4. Run `npm run content:validate`. It reads the published content with the publishable key and checks it against this app's engines.

## Updating an existing project

Run any migration in `migrations/` that the project doesn't have yet, in filename order:
- `20261027130000_lesson_categories.sql`: lesson categories. It assigns all 22 lessons when they already exist.
- `20261027130100_daily_challenges.sql`: Daily Challenge.
- `20261027140000_games.sql`: games, Game of the Week, leaderboards, Hall of Fame, nicknames, friend challenges. Then run `games/schedule.sql` so there is a Game of the Week.

- `20261028120000_rps_opponent_reads.sql`: Rock, Paper, Scissors mystery/chosen opponents and reads in the practice log (three nullable columns on `game_practice_results`; replaces `record_practice_game` and `get_my_games`). Until it is applied, the app still works but logs practice without them.

- `20261028140000_delete_account.sql`: Settings → Delete account. Adds `public.delete_my_account()`, which deletes the caller's own `auth.users` row (identity from the JWT only; signed-in users only) and, through the existing `on delete cascade` keys, all of that player's rows. It also changes `game_matches.challenge_id` to `on delete cascade`, so other players' matches on a deleted player's friend challenge go with the challenge instead of blocking the deletion. Until it is applied, Delete account fails with an error and deletes nothing.

- `20261105120000_daily_challenge_v2.sql`, `20261105120100_game_of_the_week_v2.sql`, `20261105120200_scheduler.sql`:
  Daily Challenge v2 (India-time day, automatic scenario selection, scoring, leaderboard, history) and Game of the
  Week v2 (all 23 games, rotation, manual scheduling, champions). They add tables and columns, switch the Daily
  Challenge day from UTC to Asia/Kolkata, back-fill a score on existing official daily attempts and a configuration and
  number on existing competitions, and turn finalized v1 winners into champion records. Then:
  1. deploy the Edge Function: `npx supabase functions deploy arena-match` (from the repository root);
  2. `update public.competition_settings set arena_server_enabled = true;`
  3. run `scheduler.sql` and verify it (`docs/SQL_EDITOR_OPERATIONS.md`, Part 3).
  Until step 2, Game of the Week uses the five classic games only.

None of the older ones changes existing data; the last of them only adds nullable columns. To remove the games migration (it only adds objects): drop its functions, then its tables in reverse dependency order (`competition_results`, `game_matches`, `game_practice_results`, `game_challenges`, `game_competitions`, `player_profiles`, `game_definitions`), then the `game_engine` schema — this deletes all game data.

## Daily work

```bash
npm run content:validate          # live content OK for this app version?
npm run content:pull              # record database edits in seed/content.json
npm run content:seed-sql          # regenerate seed.sql after editing content.json
```

```sql
select * from content_admin.validate_daily_challenges();   -- expect no rows
select public.finalize_due_competitions();                -- finalize any ended week now (also runs on every read)
select * from content_admin.scheduler_health;              -- the scheduler's last run per step
select * from content_admin.validate_scenario_pool();      -- expect no rows
-- publish a daily challenge: one statement, see docs/DAILY_CHALLENGE.md
```
